# tg-media-bot (Rust)

Self-hosted Telegram-бот, который скачивает видео и аудио по ссылке (YouTube, TikTok, Instagram, X, Reddit, Vimeo, SoundCloud и ещё 1000+ сайтов через yt-dlp) и присылает файл обратно в чат.

Это переписанная на Rust версия [antlis/tg-media-bot](https://github.com/antlis/tg-media-bot). Главная цель — бот не должен класть маленький VPS.

## Почему старая версия клала VPS

Что нашлось в коде Python-версии:

| Проблема | Последствие |
|---|---|
| Каждое видео шло через `--recode-video mp4` без ограничения качества | Любой WebM/MKV (VP9/AV1, вплоть до 4K) полностью перекодировался в ffmpeg на всех ядрах |
| Размер и длительность проверялись только после скачивания | Многочасовые стримы и 4K-файлы скачивались целиком, забивая диск, и только потом падали на лимите Telegram |
| 3 загрузки параллельно × `--concurrent-fragments 16` | До 48 одновременных соединений и потоков yt-dlp |
| При отмене или таймауте убивался только процесс yt-dlp | Запущенный им ffmpeg оставался сиротой и продолжал жечь CPU |
| Цепочка фолбэков: до ~9 полных повторных скачиваний одной ссылки | Одна «плохая» ссылка грузила сервер десятки минут (таймаут — час на попытку) |
| Headless Chromium (Playwright) на ошибки «unsupported URL» | +300–500 МБ RAM на каждый запуск |
| Ни у бота, ни у telegram-bot-api не было лимитов памяти и CPU | Ядро уходило в OOM, и падало всё на сервере |

## Что сделано иначе

- **Сам бот почти ничего не весит.** Однопоточный async-рантайм, 3 МБ бинарник, около **4,5 МБ RSS** в простое (измерено в контейнере).
- **Сначала проверка, потом скачивание.** `yt-dlp --dump-json` получает метаданные без загрузки. Стримы и слишком длинные ролики отклоняются сразу. Из доступных качеств выбирается лучшее, которое влезает в лимит размера, с предпочтением H.264. Результат проверки переиспользуется при скачивании, страница второй раз не разбирается.
- **Без перекодирования, когда можно.** H.264/AAC отправляется как есть. Другой контейнер перепаковывается без пережатия (`-c copy`, почти без CPU). Полное перекодирование только для коротких неиграбельных роликов (по умолчанию до 10 минут, до 720p, ffmpeg в 1 поток). Остальное уходит файлом.
- **Жёсткие лимиты.** По умолчанию 1 загрузка одновременно на весь бот. Ещё есть лимит длительности (180 мин), высоты (1080p), минимального свободного места на диске (300 МБ) и таймаут (30 мин). Если файл фактически растёт больше лимита, загрузка обрывается.
- **Дочерние процессы под контролем.** Каждый yt-dlp/ffmpeg живёт в своей группе процессов с пониженным приоритетом (`nice 10`). При отмене, таймауте или остановке бота группа убивается целиком, сирот не остаётся.
- **Файлы не грузятся в память.** Отправка в Telegram идёт потоком с диска. С локальным Bot API серверу передаётся путь к файлу, без гоняния 2 ГБ по HTTP.
- **Личная очередь до 100 ссылок.** Ссылки одного пользователя качаются по очереди, а пользователи по очереди делят общие слоты, так что длинная очередь одного не блокирует остальных. Статусное сообщение появляется только когда подошла очередь ролика, чат не заваливается сотней сообщений.
- **Вопрос о качестве.** На каждое сообщение со ссылками бот один раз спрашивает: максимум, 1080p, 720p, 480p, 360p или только аудио. Отвечать может только тот, кто прислал ссылки. Через `/quality` выбор можно запомнить, и бот перестанет спрашивать.
- **Кэш по видео, а не по ссылке.** Уже отправленное видео пересылается по `file_id` мгновенно, без скачивания и без очереди. Для YouTube, TikTok, Instagram, X, Vimeo и Reddit бот сам достаёт id ролика из ссылки, поэтому `youtu.be/X`, `youtube.com/watch?v=X&si=…` и `shorts/X` — одно и то же видео. Если по ссылке не понятно, бот берёт id из метаданных yt-dlp и сверяется с кэшем ещё до скачивания, в том числе по фактическому разрешению: запрос 1080p для ролика, у которого максимум 720p, отдаст уже загруженные 720p.
- **Защита сети.** Ссылки на `localhost` и приватные адреса (`10.x`, `192.168.x`, `169.254.169.254`…) отклоняются, бота не получится использовать для сканирования вашей сети.
- **Лимиты в Docker/systemd.** `mem_limit`, `cpus` и `pids_limit` в compose, `MemoryMax`/`CPUQuota` в systemd-юните. Даже в худшем случае бот упрётся в свой потолок, а не положит VPS.
- **Бот предупреждает**, если `TEMP_DIR` лежит на tmpfs (загрузки тогда расходуют RAM) или `ALLOWED_USERS` пуст.

### Измерения (Docker, 1 загрузка)

| Процесс | Пик RSS |
|---|---|
| tg-media-bot | ~4,5 МБ |
| yt-dlp | 60–85 МБ |
| ffmpeg (перекодирование 720p) | ~125 МБ |
| ffmpeg (перепаковка) | ~30 МБ |
| deno (только YouTube, несколько секунд) | ~250–310 МБ |

Пик всего контейнера на YouTube — около 400 МБ, на остальных сайтах — 60–150 МБ. Поэтому `mem_limit: 768m` при `MAX_PARALLEL_DOWNLOADS=1` даёт запас. Без Deno образ весит 655 МБ вместо 817 МБ, а YouTube работает с ограниченным набором форматов.

## Языки

Русский, украинский, английский, испанский. Язык выбирается кнопками: они показываются на `/start` и по команде `/lang`. Язык запоминается для каждого чата. Пока его не выбрали, берётся язык Telegram-клиента пользователя. Меню команд Telegram тоже локализовано, а в личке переключается вместе с выбранным языком.

Чтобы добавить язык, скопируйте `src/i18n/en.rs`, переведите строки и добавьте вариант в `Lang` (`src/i18n/mod.rs`). Если хоть одна строка пропущена, проект не скомпилируется. Тесты проверяют плейсхолдеры и HTML-разметку.

## Запуск через Docker (рекомендуется)

### Быстрый запуск (готовый образ, без клонирования)

Для запуска достаточно скачать `docker-compose.yml` и подготовить `.env`:

```bash
mkdir -p tg-media-bot && cd tg-media-bot

# 1. Скачиваем docker-compose.yml и шаблон .env
curl -fSL https://raw.githubusercontent.com/olluorg/tg-media-bot/master/docker-compose.yml -o docker-compose.yml
curl -fSL https://raw.githubusercontent.com/olluorg/tg-media-bot/master/.env.example -o .env

# 2. Настраиваем переменные окружения
nano .env

# 3. Запускаем
docker compose up -d

# 4. Проверяем логи
docker compose logs -f bot
```

### Минимальные параметры в `.env`:
* `BOT_TOKEN` — токен вашего бота от [@BotFather](https://t.me/BotFather).
* `ALLOWED_USERS` — числовые ID пользователей в Telegram через запятую (узнать свой ID можно в [@userinfobot](https://t.me/userinfobot)).
* `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — с [my.telegram.org/apps](https://my.telegram.org/apps). Нужны для работы встроенного локального сервера Telegram Bot API (позволяет отправлять видео и аудио до **2 ГБ** вместо стандартных 50 МБ).

> **Без локального API сервера (лимит 50 МБ, меньше памяти):** удалите сервис `telegram-bot-api` и строки `API_SERVER_URL` / `LOCAL_API_SHARED_FILES` в `docker-compose.yml`. Тогда `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` не потребуются.

### Сборка и запуск из исходников

Если вы хотите собрать образ локально на сервере:

```bash
git clone https://github.com/olluorg/tg-media-bot.git
cd tg-media-bot
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f bot
```

yt-dlp в контейнере сам обновляется раз в сутки, и только когда нет активных загрузок.

## Запуск без Docker (systemd)

Нужны `yt-dlp`, `ffmpeg`/`ffprobe` в `PATH` и, для YouTube, `deno`.

```bash
cargo build --release
sudo install -m755 target/release/tg-media-bot /usr/local/bin/
sudo install -Dm600 .env /etc/tg-media-bot/env
sudo cp packaging/tg-media-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now tg-media-bot
```

## Команды

| Команда | Что делает |
|---|---|
| ссылки (до 50 в сообщении) | бот спросит качество и поставит их в твою очередь |
| `/start`, `/lang` | приветствие и кнопки выбора языка |
| `/help` | справка и текущие лимиты |
| `/quality` | запомнить качество по умолчанию или снова спрашивать каждый раз |
| `/formats <ссылка>` | спросить качество, даже если оно запомнено |
| `/status` | твоя очередь и id загрузок |
| `/cancel [id]`, `/cancel all` | отменить загрузку (без id — единственную) или всю очередь; ещё есть кнопка ✖ под статусом |
| `/minimal on\|off` | без статусных сообщений и подписей в этом чате |
| `/topic lock\|unlock\|status` | работать только в одной теме форума |

В группах: когда разрешённый пользователь (`ALLOWED_USERS`) пишет боту в группе, группа активируется, и пользоваться ботом могут все её участники. Чтобы бот видел ссылки без упоминания, отключите Group Privacy в @BotFather.

## Настройка

Все параметры с пояснениями — в [.env.example](.env.example). Главное для слабого сервера:

| Переменная | По умолчанию | |
|---|---|---|
| `MAX_PARALLEL_DOWNLOADS` | 1 | одновременных загрузок |
| `USER_QUEUE_SIZE` | 100 | личная очередь одного пользователя |
| `RATE_LIMIT_PER_USER` | 1 | сколько ссылок пользователя качается одновременно |
| `MAX_QUEUE_SIZE` | 1000 | очередь всего бота |
| `MAX_FILE_SIZE_MB` | лимит Telegram | качество подбирается под этот размер |
| `MAX_DURATION_MIN` | 180 | длиннее — отказ до скачивания |
| `MAX_HEIGHT` | 1080 | максимальное разрешение |
| `TRANSCODE` | auto | `never` — никогда не перекодировать видео |
| `CONCURRENT_FRAGMENTS` | 4 | параллельных фрагментов HLS/DASH |
| `DOWNLOAD_RATE_LIMIT` | — | ограничение скорости, например `5M` |
| `MIN_FREE_DISK_MB` | 300 | не начинать загрузку при нехватке места |
| `CHILD_NICE` | 10 | приоритет yt-dlp/ffmpeg |

## Плагины

Для сайтов, которые yt-dlp не понимает, положите в `PLUGIN_DIR` (`./plugins` в compose) исполняемый файл на любом языке. Он получает ссылку аргументом и печатает прямой URL медиа или JSON `{"url", "referer", "headers"}`. Если ссылка не его, плагин завершается с ненулевым кодом. Плагин вызывается до yt-dlp (`TGMB_MODE=resolve`) и после неудачи всех экстракторов (`TGMB_MODE=fallback`). Пример — [examples/plugin-example.py](examples/plugin-example.py).

Встроенного headless Chromium больше нет: если он действительно нужен, его можно подключить как fallback-плагин.

## Переезд с Python-версии

Бот сам импортирует старые `allowed_chats.json`, `minimal_mode.json`, `topic_locks.json` и `media_cache.json`, если найдёт их в `DATA_DIR` при первом запуске. В Docker скопируйте их из старого тома `bot-logs` в новый том `bot-data`, например:

```bash
docker run --rm -v tg-media-bot_bot-logs:/old -v tg-media-bot_bot-data:/new alpine sh -c 'cp /old/*.json /new/ && chown 1000:1000 /new/*.json'
```

Отличия: вместо `/audio` и `/video` — вопрос о качестве и `/quality` (режим «аудио» из старой версии переносится как запомненный выбор), плагины теперь исполняемые файлы, а не Python-модули.

## Диагностика

Проверить скачивание без Telegram (yt-dlp, ffmpeg, лимиты):

```bash
docker compose run --rm bot fetch "https://youtu.be/..."          # видео
docker compose run --rm bot fetch "https://youtu.be/..." audio    # аудио
docker compose run --rm bot fetch "https://youtu.be/..." 480      # с ограничением высоты
```
